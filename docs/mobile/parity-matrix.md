branch `arena/01a0b91b-researchengine`. This checkout

### 1.1 Rows where I disagree with the brief's placement

1. **`Search across your own documents` — placement agreed (Device), premise rejected.**
   There is no local index today (no FTS, no `BUDGET_MS`, no `why()`); the matrix row
   in the brief describes machinery that isn't in this checkout. The port must build
   it in `re-core` and *then* claim the 10 ms tier.
2. **`Export/import ZIP` — Hybrid agreed, but the ordering constraint it hides is not stated.**
   Store-scoped ZIP + localStorage state means "copy the library folder" is a promise
   the *desktop* has to upgrade before the phone can honor it (R2 acceptance test).
3. **`Agent Flood` — placement agreed, one dependency added.** The companion scale
   needs the desktop to grow a real flood job API (orchestrator exists unrouted).
4. **`17 provider entries` — row reduced to 11 + count kept honest.** No mobile-side
   registry forks; `packages/registry` is the single source so 0.36's 17 arrive by
   merge, not by port.
5. **`Read & Quiz` — Device agreed, but Reader300 is not "a port"; it's an invention.**
   Mark it as new-capability work with its own budget scene, so nobody "proves" the
   native-island question against a reader that doesn't exist yet.
6. **`Free routing`, `Humanize`, `Share Studio`, `Tasks checklist`, `Dictation`, `:dot:`
   formatting, `Design mode`, `Try a sample app`** — the brief lists them as existing
   features; they do not exist in 0.16.0-beta.1. Mobile cannot "keep" them. Either the
   port rebases onto a branch where they exist (recommended before R7) or these rows
   move from *parity* to *parity-with-0.36* and gate R9's honesty table.
