# Local Board — storage and first workspace checkpoint

Current cross-product roll-up: [implementation-status.md](implementation-status.md). Sections below are historical checkpoints; use the roll-up and later checkpoints rather than an early “remaining work” paragraph in isolation.

Implementation progress, not a release note. The first local workspace is now available at /board (sidebar More tools → Board). This is not the complete Board milestone.

## Implemented

`frontend/src/lib/board/storage.ts` defines version-1 Board documents with stable UUIDs, revisions, viewport, typed item kinds and optional attachment/page provenance. Items have geometry, plain text, grouping and connector references, and drawing points. This is an extensible first schema, not a completed rich-text/drawing editor. No HTML rendering, fetching source URLs, provider calls or networking occurs here.

Native IndexedDB is used without a new dependency. Documents, immutable board-scoped Blob attachments and the previous committed document share one transaction. Save resolves after transaction completion, not after individual put requests. Expected revisions prevent stale windows silently overwriting changes. Each successful edit retains the previous snapshot; an explicit restore can save it as a new revision, retaining the latest document as the next recovery snapshot. Validation rejects unsupported versions, duplicate IDs, invalid geometry, missing linked items, cyclic groups and missing attachments without resetting existing data. Attachment IDs use composite IndexedDB keys, not delimiter-concatenated keys.

## Honest limits and next work

Attachment import and selected-card image/PDF previews are implemented in the next checkpoint below. Next: direct card manipulation, attachment-complete backup/import and richer editing. Rich text, drawings, shapes, connectors and frames need actual editing tools; their schema presence is not delivered functionality. Board-to-session and mandatory model confirmation remain later work.

IndexedDB is browser-profile local. Storage eviction, user-cleared browser data, OS/hardware failure and private browsing can still lose data. A previous document is not an off-device backup, full operation journal, or crash-proof guarantee. Attachment deletion/garbage collection, full export/import backup and process-kill recovery tests are not implemented yet. Opening blocked storage reports an actionable error; per-tab draft quota failures are visible. Actual disk-full/native-device failure testing remains unperformed. Teams transactions, durable server acknowledgements, encryption, permissions, reconnect and collaboration are not implied by this local API. No security/encryption certification or native-device claim.

## Attachment checkpoint

Board now has an explicit **Import & save files** action. It validates/decode-checks PDF, PNG, JPEG and WebP by content, then commits all new originals/cards and the current document draft in one transaction. The UI discloses that this saves the entire current draft. Validation failures/cancellation do not partially add cards, and failed commits retain the prior revision and existing in-memory draft. No arbitrary upload-MB cap; actual browser storage/memory limits still apply and are disclosed. Files are not uploaded or sent to providers.

One card is initially created for each original. A PDF card starts linked to page 1 and its inspector can select another valid page. The page number is persisted on the card, not inferred from text. Original Blobs are immutable and namespace/board scoped. The selected card alone loads/decode-renders a preview; other cards show file/page labels. This is not yet a gallery of canvas thumbnails or multi-page-card duplication. Image/PDF attachment labels can be annotated in the existing editor. Download original returns the saved bytes, while Download draft remains document JSON only (not a file-complete backup).

The installed pdf.js renders a bounded-resolution canvas, with selectable page text exposed in a disclosure. No PDF annotation/JavaScript/form/link execution UI or embedded browser PDF iframe. Eval/XFA/worker fetching are disabled in the Board loader. Scanned/blank pages remain previewable; missing selectable text is described honestly without claiming OCR. Password errors advise unlocking a copy; password handling was not independently tested with an encrypted fixture. Page-raster bounds (800×1000 target) are a preview resource limit, not an original-file size cap.

Validation progress counts actual completed files. Cancellation is cooperative across file reads/decode and aborts the IndexedDB commit if still pending. No timer-driven percentage. The existing extraction island's extraction-only semantics are unchanged; this Board-specific validation/save action reports its own inline status. Board originals are not given a misleading extraction-ready state. The store's optional AbortSignal also passed a transaction-abort test with no document or Blob leakage. Selecting another card releases image URLs/PDF resources; no eager whole-board PDF rasterization.

## File-complete backup checkpoint

**Download full backup** exports the current draft document plus every distinct linked original to a local `.reboard` file. It does not commit a revision. Removed/unreferenced originals, previous revisions, other boards and tab recovery history are intentionally excluded. The older Download draft action remains document-only JSON and is not a supported import file. The editor and board list both offer **Import backup as new board**; an import never overwrites the source/current board. Imported board, item and attachment IDs are fresh; group/connector references are remapped. Imported boards begin at saved revision 1 in the active local namespace. Leaving an unsaved draft to import requires confirmation advising save/download first.

The unencrypted v1 container is deliberately uncompressed: ASCII `REBOARD1`, a four-byte unsigned big-endian JSON-manifest length, UTF-8 manifest, then consecutive raw original bytes in manifest order. Manifest fields are `format: research-engine-board`, `version: 1`, `document`, and `attachments` entries (`id`, `name`, `size`, lowercase hex `sha256`). Names are metadata, never extraction paths. Exact safe-integer payload lengths and complete coverage are required: duplicates, unreferenced/missing originals, truncation and trailing bytes are rejected. Each original's SHA-256 is checked and then its actual content decoded through the existing image/PDF validator. Card kind and linked PDF page must match the original. Document schema, links and group cycles are validated. Only after all checks does the existing transaction save the complete separate board and originals with cancellation/write-freeze protection.

Checksums cover original bytes, not a signed/authenticated document. They detect accidental payload corruption, not authorship or hostile tampering. This is not encrypted backup, an antivirus scanner, or a guarantee that arbitrary PDFs/images are safe. Keep files private. Export/import currently materializes manifest/hash buffers in memory; no streaming/large-device-memory certification or arbitrary MB cap is claimed. Manifest length is limited by the format's uint32 field. Browser quota/memory limits can fail the operation. Cancellation is cooperative between reads, hashing and decode, and can abort a still-pending save transaction; it cannot undo an already committed transaction or an already requested browser download. Download status says requested, not written to disk.

`tools/design/check-board-backup.mjs` passed using real browser PNG/PDF data: UI download and separate-board import including unsaved annotation and linked PDF page; fresh IDs; unchanged source revision; byte-exact original; corruption/truncation/version/duplicate/missing/trailing-byte rejection; valid-checksum unsupported-content rejection; abort and missing-original export; empty roundtrip; cancellation while image decode is held without partial board creation; namespace isolation; narrow horizontal bounds; no external HTTP requests or page errors. Desktop and narrow screenshots inspected. Workspace, manipulation, attachment and storage browser regressions, 16 BoardUI checks, TypeScript, diff check and production frontend/backend build passed. Physical devices, screen readers, browser process kills, huge files, disk-full downloads and hostile-format security certification remain untested. ## Shapes and frames checkpoint

Board now creates labelled rectangle/ellipse/diamond shapes and named frames. Shape outlines use original SVG primitives with inherited theme/forced-colour tokens (no imported artwork or dependency). Shape selection, move/resize, plain/Markdown labels, draft recovery, explicit save and full backup use the existing item workflow. A missing shape variant defaults to rectangle for older documents; unknown variants or a shape variant attached to a non-shape fail validation. Shape labels are clipped within a centred region; this is not auto-fit typography, rotation, colour styling or vector export.

The inspector offers explicit frame membership for items, including nested frames. Self and descendant frames are excluded from parent options; existing schema cycle validation remains the final save/import guard. Positions remain absolute board coordinates; dropping or overlapping does not change membership. Frame geometry edits translate the complete membership tree by the same delta. Negative translation clamps against the earliest member coordinate so existing non-negative members do not cross the origin or lose relative spacing. Numeric fields, keyboard handle arrows and pointer drags share the translation helper. Pointer tracking writes temporary transforms for the frame and its members without per-move document state; release creates one undo entry and Escape restores all previews. Resizing a frame changes only its boundary and never scales/moves members. Removing a frame retains children and removes direct parent links; undo restores the original tree.

Frames render behind ordinary cards and stay behind them even when selected. Use the outline/inspector or keyboard handles when overlapping cards obstruct a frame's pointer target. There is no automatic containment, auto-layout, clipping to frame bounds, selection marquee, arbitrary multi-selection, collapse, layer-order editor or group transform handles. ## Directed connector checkpoint

Board can now create a directed connector when at least two non-connector items exist. Creation uses the selected eligible item (or first eligible item) as source and another item as target, then opens explicit endpoint selectors and a plain-text connection label. Endpoint choices exclude the opposite endpoint and other connectors. Self-links and connector-to-connector references fail schema validation. Incomplete legacy connector records remain readable and selectable in the outline for endpoint repair; they do not render a misleading path until both endpoints resolve. Labels retain full source in the inspector; the canvas shows only the first line, capped at 80 characters.

Connectors render as SVG arrows, not movable/resizable cards. Anchors use rectangle, ellipse or diamond boundary intersections along the centre-to-centre direction; coincident centres use a visible curved route. Routing does not avoid obstacles or label collisions, and overlapping/nested endpoints can cross other objects. There are no manual ports, bends, line-style controls, drag-to-connect gesture or self-loop tools in this slice. An expanded transparent stroke provides pointer selection, with Enter/Space keyboard selection and the outline as another selection route. Normal save/recovery/backup stores stable endpoint IDs; backup import remaps them. Removing an endpoint removes its incident connectors in the same undoable draft edit. Removing a frame still retains its contents, while connectors incident on the removed frame itself are removed. The confirmation explicitly describes both effects.

## Freehand drawing checkpoint

**Draw stroke** enters a one-stroke pointer mode on the canvas; release creates one drawing item and returns to selection. A stationary press creates a dot. Primary mouse/touch/pen pointer events use pointer capture; right-button and secondary pointers do not start strokes. Coordinates account for the scaled, scrolled canvas and clamp to its current bounds. Tracking writes only a temporary SVG path, with samples separated by at least one board unit (release includes the last point), not per-pointermove document/history updates. Escape discards and exits; pointer cancellation, lost capture, window blur, unmount or relevant disabled/geometry changes clear an in-progress path. Busy/recovery/wipe guards apply, and entering Draw disables existing item handles. There is no inertia, auto-pan or background network/provider activity.

Each committed stroke has its own item ID, outline selection, annotation/plain-or-Markdown editor, frame membership, move/resize handles and connector eligibility. It uses the existing undo/recovery/explicit-revision/backup workflow. New strokes store `pointSpace: 'unit'` with finite points inside the unit box, plus absolute item bounds. Moving preserves normalized points; resizing scales the path, not its fixed stroke thickness. Unit drawings require at least one point and validate the marker/kind/range on save and import. Legacy unmarked drawing records are still readable and render their points in local item coordinates; new normalized-resize guarantees apply to newly authored unit-space drawings. No automatic destructive migration of old points.

**Draw with coordinates (keyboard alternative)** accepts user-authored finite non-negative X,Y board points, one pair per line, joined in order. Invalid input shows the failing line without adding an item. One point makes a dot. The resulting geometry is generated by the same normalizer as a pointer stroke, not a canned illustration. Annotation text lets users describe visual strokes. This is not a full screen-reader drawing application; physical-device and assistive-technology testing remain pending.

The first version has fixed theme-aware 2.5-unit round strokes. There is no pressure/tilt sensitivity, brush palette, smoothing/beautification, partial eraser, point editor, multi-stroke compound object, raster export, unlimited canvas growth or Draw-mode panning/pinch zoom. Remove item removes the whole stroke (and incident connectors) with existing undo semantics. Stroke sampling is not a fidelity-preserving recording of every hardware sample, and very long paths consume browser memory/tab-recovery quota; no large-drawing performance guarantee or new arbitrary point-count cap is claimed.

## Board deletion and original cleanup checkpoint

Explicit lifecycle controls now supersede the earlier “deletion/GC pending” notes. The board list offers a confirmed Delete action; the editor's **Board storage and deletion** disclosure offers **Clean unused originals** and **Delete this board**. Editor maintenance is disabled for unsaved changes, pending recovery decisions, Draw mode and busy/wipe states. Confirmation describes irreversible effects, backup advice, other-tab draft risks and the lack of secure disk erasure. Deletion also attempts to clear this tab's recovery draft; failure to clear that entry is reported after the successful database deletion, not misrepresented as a database rollback.

The store's `maintain(id, expectedRevision, operation)` opens one read/write transaction across the document, previous revision and originals. It validates saved snapshots and checks the expected current revision before changing anything. Cleanup keeps the union of attachment IDs referenced by the current and previous saved revisions, deleting only unreferenced originals for that exact board. Delete removes both revisions and every stored original for that board. A compound-key cursor is bounded by the exact board ID, not string-prefix matching; another board with a similar ID and another namespace remain untouched. Counts and bytes are returned only after transaction commit. Cursor/validation/write failures abort the transaction. No automatic cleanup on save, load, tab close or timer was added.

Cleanup does not advance the document revision or change the previous snapshot. An original removed from the current draft remains protected while referenced by the previous saved revision; it becomes eligible only after that snapshot ages out and the user explicitly cleans up. Older unsaved tab drafts are not retained-reference roots: save/download them before cleanup. Other windows are not remotely closed or stripped of their in-memory copies. Normal stale editor saves (with the deleted board's nonzero revision) fail rather than resurrect the board; this is not an origin-wide tombstone or a claim that arbitrary same-origin scripts cannot deliberately create a new revision-zero document under a reused ID. Browser/OS remnants, downloaded backups and files already held in memory are not securely erased.

## Board-to-session checkpoint

**Board to session** opens an inspector workflow with an initially empty, mandatory model selector. It lists only configured providers with cached fetched models (and a stored key when required), excludes decision-only providers, and does not infer the global default or invoke Free Routing. The user chooses output intent, task, estimated input budget, maximum output tokens, item inclusions/exclusions and whether linked PDF pages contribute selectable text. Preparing reads selected originals locally; it does not call a model. Any extraction failure or cancellation prevents publishing a partial snapshot. Changing the Board or setup options invalidates the prepared review/consent.

A prepared snapshot contains stable Board/item IDs, saved base revision plus a draft marker, exact selected item text/metadata/geometry, optional complete linked-page PDF text, original metadata, and excluded item IDs. Original bytes, image pixels, OCR, visual interpretation of drawings and remote URL fetching are explicitly excluded. Relations can reference an excluded ID, but the excluded item's contents are absent. The system asks for `[board:ITEM_ID]` citations and warns against claiming unseen evidence. This is structured source context, not guaranteed citation correctness or a prompt-injection security boundary. There is no hidden content truncation or visual-to-text substitution represented as vision.

The user reviews exact system/context text and confirms creation of an independent local research session. Creating it still sends nothing. The frozen context, provider/model identity (including colon-containing model IDs), endpoint, intent, budgets and source manifest are copied into the chat record in one store update. They do not point at live Board text. Later source edits/deletion do not change the snapshot; deleting the source Board does not delete this copied chat. Sessions use existing profile-scoped, deferred chat persistence, not Board's IndexedDB revision transaction. Browser clearing/quota/process failure can lose chat data; no stronger crash-durability guarantee is claimed. Board `.reboard` backups do not include these separate chat sessions. Cross-product session export/import fidelity has not been certified here.

The dedicated session view shows the pinned model/endpoint, local snapshot origin, exact next system/messages, estimates and a fresh send confirmation. The top bar shows a pinned model label rather than the global picker and hides the family-table context-window meter for this route. First send and every follow-up require consent; there is no auto-send on navigation/reload. The normal chat runner refuses snapshot sessions, preventing its pruning/cache/free-route/demo/tool pipeline from handling them. Snapshot requests go through the existing streaming adapter with verbatim reviewed system text (no automatic app-context/memory/persona injection), no tools/web/council and no model substitution. Ollama snapshot requests use the same-origin backend proxy and its OpenAI-compatible `/v1` API, not a browser request to sandbox localhost. Other chat callers keep their existing behavior.

Input estimates are `ceil(characters / 4)`, not model tokenization. The application sends the whole reviewed input or blocks when its estimate exceeds the user's explicit input budget. Maximum output is sent as chosen; provider context limits, tokenizer behavior and server-side truncation policies are not verified. Input/output budgets and model remain fixed for the session; create a new reviewed snapshot to change them. Full successful history is retained in follow-ups, not compressed. Failed/stopped assistant output remains visible locally but is explicitly excluded from future requests; retry reuses the reviewed request without silently duplicating its user turn. Provider errors, missing models/keys, locked keys and changed endpoints fail visibly. Privacy Shield changes block the send instead of silently redacting the reviewed payload; its pattern scanner may produce false positives. Existing daily-budget checks apply.
